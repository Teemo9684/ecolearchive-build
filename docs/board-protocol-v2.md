# EcoleArchive → Google TV protocol v2 (implementation candidate)
PC serves only encrypted approved BoardSnapshot; no raw archive endpoints. User enters private PC and TV IPv4 addresses and port (default 8765). The server accepts only the configured TV source IP and exact GET paths. No listener starts automatically. Key is 32 random bytes represented by 64 hex characters; manually provision TV. HTTP carries ciphertext only; metadata is not confidential/authenticated. Do not expose port to internet. Native Android HTTP client required; no CORS support. 
GET /tv/v2/manifest.json returns protocol=2, revision, sha256 (hex over binary), bytes, cipher=AES-256-GCM. GET /tv/v2/snapshot.bin returns 12-byte random IV then AES-GCM ciphertext with 16-byte tag; AAD UTF-8 ecolearchive-board-v2. Decrypt with paired key; verify schemaVersion=1, revision and approvedAt, bounds, allowlisted fields, asset types, page IDs, row counts and duration. Reject replay of older approvedAt (persist highest accepted, handle explicit reset); stage and atomically persist only after successful verification. Keep last valid snapshot offline. Package maximum plaintext 32 MiB. Store keys in Android Keystore; avoid logs; provide pairing and reset. No demo data fallback in production. 
Render pages in exact order, including repeated kinds. PDF and PNG/JPEG/WebP assets are data URLs; use native PDF renderer, never execute active document content. Match RTL and fonts, manual remote interaction interrupts autoplay. No receiver acknowledgement is implemented: PC status only means listening, not TV delivery. This contract requires receiver implementation and security/interoperability review before real deployment.
